# Lumora Private-Beta Feedback Form

**Use this form after a real workflow attempt.** It is designed to capture evidence, not endorsements. Submit one form for each material workflow attempt, including an approved output, a rejection, an abandonment, or a technical failure.

> Do not include passwords, API keys, platform access tokens, payment data, or unredacted confidential source material. Use workspace, content, run, and review-gate identifiers instead.

| Question | Response |

## E. Cost, value, and willingness to pay

Answer this only after at least one complete HRG decision. There is no correct answer, and no price is being imposed by this form.

| Prompt | Response |
|---|---|
| What outcome would make this workflow worth using again? |  |
| If this solved that outcome reliably, what pricing model would you expect? | Per output / per workspace / usage-based / other / unsure |
| What monthly or per-output range would you seriously consider? | Optional range and currency; explain conditions. |
| What would make the product not worth paying for? |  |
| Would you be willing to discuss a paid design-partner arrangement after the beta? | Yes / no / maybe; contact preference. |

Generic praise, hypothetical interest, and a survey answer without actual use are not treated as willingness-to-pay evidence. A later payment, signed price-range commitment, or documented decision after repeat use is needed before a commercial claim.

## F. Open feedback

1. What should we keep exactly as it is?
2. What should we change before you attempt a second workflow?
3. What was surprising or confusing?
4. What feature should **not** be added until the core workflow works better?
5. May we quote this feedback internally? Yes / no. If yes, specify whether attribution is allowed.
